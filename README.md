# ZQ-CSP

**ZQ-Check and Search Proxy**

一个运行在 Cloudflare Workers 上的单文件代理检测与优选工具。它从公开数据源抓取代理候选，真实建立连接去实测，把「是否可用 / 延迟 / 出口 IP / 国家地区 / 命中机房」写入 KV，并提供一个网页面板用于查看、优选和导出订阅。

整个项目只有 `_worker.js` 一个文件，不依赖 wrangler，不需要构建，也不需要安装依赖。

---

## 功能

- **抓取**：七类候选（SOCKS5、HTTP、HTTPS、SSTP、ProxyIP、CF IP、CF 域名）的候选来源均可在面板中配置，每类支持多行来源。
- **检测**：前五类由 Worker 真实建立隧道发起请求；CF IP 与 CF 域名由访问者浏览器发起请求，测量的是本机到 Cloudflare 边缘的延迟。
- **优选**：按延迟排序，可设地区、并发、超时与抽样数量，分批执行，可随时暂停与继续。
- **导出**：面板一键复制结果，或通过 `/list/*` 获取纯文本 / JSON 订阅。

---

## 支持的七类

| 类型 | 面板标签 | 检测方式 | 默认来源 |
| --- | --- | --- | --- |
| `socks5` | SOCKS5 | 完整 SOCKS5 握手后发起 HTTPS 请求 | EDT-Pages/Proxy-List |
| `http` | HTTP | HTTP 代理绝对 URI 请求 | EDT-Pages/Proxy-List |
| `https` | HTTPS | HTTP 代理 + TLS 隧道 | EDT-Pages/Proxy-List |
| `sstp` | SSTP | 自实现 SSTP/PPP 客户端 | VPN Gate 官方源与镜像 |
| `proxyip` | ProxyIP | 作为 Cloudflare 回源地址直连验证 | cmliu 公开列表 |
| `cfip` | CF IP | 浏览器经泛解析域名访问目标 IP，请求 `/ip.json` 计时 | 七份 CF 段表 |
| `cfdomain` | CF 域名 | 浏览器请求该域名的 `/cdn-cgi/trace` 计时 | CF-Pages 域名名单 |

前五类的候选来自第三方公开列表，可用性由对方维护。CF IP 与 CF 域名测的是 Cloudflare 边缘的响应速度，结果中的国家与机房为请求实际落点。

## 部署

### 1. 创建 Worker

Cloudflare 控制台 → **Workers 和 Pages** → 创建 Worker → 编辑代码 → 用 `_worker.js` 的全部内容覆盖 → 保存并部署。

### 2. 绑定 KV

**设置 → 绑定 → KV 命名空间**，新增一条：

| 字段 | 值 |
| --- | --- |
| 变量名称 | `CSP` |
| KV 命名空间 | 任选一个（没有则新建） |

变量名称必须为 `CSP`，否则面板会提示未绑定。

### 3. 定时任务（可选）

**设置 → 触发器 → Cron 触发器**，按需要填写频率。定时任务的行为见下文「定时优选」。

### 4. 设置管理密码

打开 `https://你的域名/admin`，首次进入会要求设置管理密码（至少 4 位）。密码以哈希形式存入 KV，登录成功后下发 Cookie。修改密码在面板「设置」中操作，修改后旧 Cookie 立即失效。

## 面板

顶部按类型分页：**概览 / SOCKS5 / HTTP / HTTPS / SSTP / ProxyIP / CF IP / CF 域名**。

**概览页**：各类型的可用数量、候选与已测进度、最快延迟，以及全部可用节点的汇总表。

**类型页**：

- 指标：候选、待测（CF 两类显示为待测 IP / 待测域名）、已测、可用、最快。
- 开始优选 / 继续优选 / 暂停优选。停在半途的轮次可以继续，不清空已有结果。
- 选择地区（前五类）。CF IP 与 CF 域名没有地区概念，不显示该按钮。
- 来源下拉：决定本轮测哪一份来源。切换来源不会作废旧结果。
- 来源按钮：打开来源管理，按行编辑名称与地址，保存后按新地址重新拉取候选。
- 参数：并发数量、超时时间；前五类另有自动优选数量，CF IP 另有每次拉取。
- 单点测试：输入一条地址立即检测。
- 结果表、清空结果、运行日志（各类型独立记录）。

进入面板时会自动拉取七类的候选，依次拉取每类的全部来源，合并去重。

**参数说明**

| 参数 | 作用范围 | 说明 |
| --- | --- | --- |
| 每次拉取 | 仅 CF IP | 每份段表各取多少条候选，默认 512 |
| 并发数量 | 全部类型 | 同时检测的条数，默认 16 |
| 超时时间 | 全部类型 | 单条超时，默认 10000 ms；CF 两类默认 500 ms |
| 自动优选数量 | 前五类 | 定时任务每轮实际检测的条数，默认 20 |

参数按类型分别保存，修改后即时写入配置。CF 域名使用整份候选名单，不做条数截断。

## 定时优选

Cron 每触发一次只处理**一个类型**（前五类代理；CF IP 与 CF 域名不参与定时优选），按类型顺序轮转，游标保存在 `meta.autoCursor`。

单轮流程：

1. 只拉取该类型**当前选中的那一份来源**，其它来源在池中的候选保持不动。
2. 按该类型设置的「自动优选数量」抽样；优先取所选地区的节点，不足时从剩余节点随机补齐。
3. 以重新开始的方式检测一轮，结果作为该类型的最新一轮。
4. 运行摘要写入 `meta.lastAuto` 与 `meta.lastAutoAt`。

需要注意的几点：

- 必须先选择地区，未选地区的类型会被跳过。
- 抽样用于控制单次调用的子请求数。Cloudflare 免费套餐对单次 Worker 调用有子请求上限，因此每轮只测抽样数量，不跑全量。
- 地区只能选择一个，多选不生效。

## 订阅

```
https://你的域名/list/socks5?token=<订阅令牌>
```

- 令牌在面板「设置」中查看与复制，只能读取订阅与 `/check`，不能登录后台。
- 不带 `format` 参数时输出纯文本，每行 `地址#备注`，备注形如 `SOCKS5-中国香港-123ms`；CF 两类的地区取命中机房所在国家，例如 `CF IP-中国香港-62ms`。
- `?format=json` 输出结构化数据，包含协议、地址、延迟、出口 IP、国家与机房。
- `<类型>` 可填 `socks5` / `http` / `https` / `sstp` / `proxyip` / `cfip` / `cfdomain`，`all` 表示全部类型。

## KV 数据

| Key | 内容 |
| --- | --- |
| `pwd` | 管理密码哈希 |
| `sub_token` | 订阅令牌 |
| `config` | 面板配置（来源、来源选择、各类型参数） |
| `pool:<类型>` | 该类型的候选池 |
| `best:<类型>` | 该类型的优选结果与进度 |
| `region:<类型>` | 该类型的地区 |
| `meta` | 定时任务游标与运行摘要 |

删除 `pool:*` 或 `best:*` 只影响候选与结果，重新进入面板即会重新拉取，密码、令牌与配置不受影响。

## 常见问题

**提示未绑定 KV 命名空间**
KV 绑定的变量名称必须填 `CSP`，修改后重新部署。

**定时任务没有执行**
Cron 触发器需在控制台手动绑定。判断是否执行过：查看概览页的「上次完成优选」时间，或登录后在控制台执行 `fetch('/api/state').then(r=>r.json()).then(j=>console.log(j.meta))`，`lastAuto` 只有定时任务会写入。

**定时任务报 Too many subrequests**
触发了单次调用的子请求上限。可降低并发数量，或减少自动优选数量。

**定时任务执行后候选数变少**
定时只拉当前来源，并按抽样数写回池子，其它来源的候选保留。点顶部刷新按钮可重新拉取全部来源。

**选择了 v6 段表却大面积失败**
段表按来源原样提供，不做地址族筛选。本机没有 IPv6 出口时，检测 IPv6 地址会失败，属于预期结果。

**切换来源后结果还在**
切换来源只影响后续检测，不会清空已有结果。
