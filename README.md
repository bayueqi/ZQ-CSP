# ZQ-CSP

**ZQ-Check and Search Proxy**

一个跑在 Cloudflare Workers 上的**单文件**代理检测与优选工具。它会定时从公开数据源抓取代理候选，**真的把隧道建起来**去实测 `cloudflare.com` 的 `/cdn-cgi/trace`，把「通不通 / 延迟多少 / 出口 IP / 落在哪个国家 / 命中哪个 CF 机房」全部落库，再用一个网页面板按协议分页展示、优选、导出。

> 整个项目只有一个 `_worker.js`，不依赖 wrangler、不需要构建、不需要 npm。

## 它能做什么

| 能力 | 说明 |
| --- | --- |
| 抓取 | 定时（Cron）/ 手动从公开数据源拉取 socks5、http、https、sstp、proxyip 五类候选 |
| 实测 | 按协议真实建立隧道，明文 HTTP 请求 `cloudflare.com:80/cdn-cgi/trace`，读取 `ip=` / `loc=` / `colo=` |
| 优选 | 按延迟排序、按地区过滤，分批执行且可随时暂停，结果落库 |
| 展示 | 网页面板按协议分页，显示地址、延迟、出口 IP、国家/地区、命中机房 |
| 导出 | 每种协议一键复制「地址#备注」，或通过 HTTP 接口拿纯文本 / JSON 订阅 |

**注意**：这里是**真的建隧道**去测，不是 socket 握手探活。所以一个节点在面板上显示可用，意味着它在 Cloudflare 的网络里确实能连通到目标。

## 支持的协议

| 协议 | 面板标签 | 检测方式 | 候选来源 |
| --- | --- | --- | --- |
| SOCKS5 | SOCKS5 | 完整 SOCKS5 握手 + CONNECT 后发 HTTP | EDT-Pages/Proxy-List |
| HTTP | HTTP | HTTP 代理绝对 URI 请求 | EDT-Pages/Proxy-List |
| HTTPS | HTTPS | HTTP 代理 + TLS 隧道 | EDT-Pages/Proxy-List |
| SSTP | SSTP | 自实现 SSTP/PPP 客户端（LCP/PAP/IPCP + 内层 IP 包） | VPN Gate |
| ProxyIP | ProxyIP | 作为 Cloudflare 回源 IP 直连验证 | cmliu 公开列表 |

> 数据源在 `DEFAULT_SOURCES` 里，全部是公开仓库 / 公开接口，可自行替换。

## 部署步骤

### 1. 创建 Worker

Cloudflare 控制台 → **Workers 和 Pages** → 创建 Worker → 编辑代码 → **把 `_worker.js` 的全部内容粘进去覆盖** → 保存并部署。

### 2. 绑定 KV

**设置 → 绑定 → KV 命名空间**，新增一条：

| 字段 | 值 |
| --- | --- |
| 变量名称 | `CSP` |
| KV 命名空间 | 任选一个（没有就新建一个） |

> **变量名必须是小写的 `CSP`**，代码里所有读写都走 `env.CSP`。名字填错会在面板上报「未绑定 KV 命名空间」。
> 命名空间本身叫什么无所谓，数据存在命名空间里，换名字不会丢数据。

### 3. 设置定时任务（可选）

**设置 → 触发器 → Cron 触发器**，填你想要的频率，例如每 30 分钟一次。

定时任务逐类跑 `autoTypes` 里列出的协议，每轮每类**固定只测 20 条**：

- 先取**设置里的「定时优选地区」**（默认「香港」）的节点；
- 该地区节点**不足 20 条**时，从候选池其余部分随机补齐到 20 条；
- 候选池总量不足 20 条时，有多少测多少。

固定抽样是为了限制单轮请求量——Cloudflare 免费版单次 Worker 调用有子请求数上限，
逐类全量扫描很容易整轮失败。地区优先 + 随机补齐，既保住地区偏好，又让每轮负载恒定。

### 4. 首次进入并设置密码

打开 `https://你的域名/admin`，首次进入会引导你**设置管理密码**（至少 4 位）。

密码在 KV 里存的是哈希值，登录成功后下发 Cookie，**地址栏不会残留明文密码**。想改密码在面板「设置」里操作。

## 面板功能

顶部横向分页：**概览 / SOCKS5 / HTTP / HTTPS / SSTP / ProxyIP**。

概览页：

- 按协议汇总的指标卡：候选数、已测数、可用数、进度
- 一轮优选的运行摘要与时间

协议页：

- 单点测试：粘贴一条地址，立刻测它通不通、延迟多少、落在哪里
- 开始 / 暂停优选：分批跑，进度条实时更新，点暂停后当前这一片跑完即停
- 结果表格：地址、延迟、出口 IP、国家/地区、命中 CF 机房（colo）
- 一键复制结果、清空结果
- 运行日志：每个协议各自独立，不串台

登录与安全：

- `/admin` 首次访问设密码，之后登录用 Cookie 认证
- 修改密码后旧 Cookie 立即失效
- 面板对手机端做了适配（分页可横向滑动、指标卡两列排布）

## 对外接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 302 跳转到 `/admin` |
| GET | `/admin` | 管理面板（未设密码时引导设置） |
| GET | `/health` | 存活探针，返回 `{ ok: true, time }` |
| GET | `/check?<协议>=<地址>` | 单点检测，例如 `/check?socks5=host:port` |
| GET | `/list/<协议>` | 该协议优选结果，默认 `text/plain`；`?format=json` 返回 JSON；`all` 表示全部协议 |
| GET | `/api/state` | 面板数据（配置 + 各协议统计 + 结果） |
| POST | `/api/setup` | 首次设置管理密码（仅在未设密码时可用） |
| POST | `/api/login` | 密码登录，成功后下发 Cookie |
| POST | `/api/pwd` | 修改管理密码 |
| POST | `/api/config` | 保存配置（定时优选地区 / 并发 / 超时） |
| POST | `/api/fetch` | 拉取某类候选并写入 KV |
| POST | `/api/region` | 设置某类协议的地区过滤 |
| POST | `/api/optimize` | 分批优选某类，一次调用测一小批并返回进度 |
| POST | `/api/test` | 单点测试一个地址 |
| POST | `/api/clear` | 清空某类结果 |

除 `/api/setup`、`/api/login`、`/api/state` 等公开入口外，其余 API 都需要鉴权。

`/check` 返回示例：

```json
{
  "success": true,
  "proxy": "socks5://host:port",
  "ip": "104.16.x.x",
  "loc": "HK",
  "colo": "HKG"
}
```

## 导出订阅

访问 `/list/<协议>` 取该协议的优选结果，**需要带上令牌**：

```
https://你的域名/list/socks5?pwd=<令牌>
```

- 不带参数时按 `text/plain` 输出，每行 `地址#备注`，备注形如 `SOCKS5-中国香港-123ms`
- 加 `?format=json` 输出结构化 JSON
- `<协议>` 可填 `socks5` / `http` / `https` / `sstp` / `proxyip` / `all`

**令牌就是面板里显示的订阅令牌**（面板中可直接复制）。它只能读订阅，**不能登录后台**，可以放心放进客户端。

## 配置项

面板「设置」里可改：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 管理密码 | — | 留空表示不修改；填写时至少 4 位 |
| 定时优选地区 | `香港` | 定时任务与优选时优先的地区，填国家中文名或两位国家码（如 `香港` / `HK`） |
| 并发 | 16 | 同时检测的条数 |
| 超时 | 10000 ms | 单条检测超时，所有协议统一使用；网络慢时建议调大 |

单次优化调用的时间片是内部固定值（5000 ms），不暴露在面板里——它同时也是「暂停优选」的响应上限：点暂停后，当前这一片跑完才会停。

定时任务每轮每类固定测 20 条（常量 `AUTO_FALLBACK_SAMPLE`，见 `_worker.js`），可在源码里调整。

## KV 数据说明

| Key | 内容 |
| --- | --- |
| `pwd` | 管理密码的哈希值 |
| `config` | 面板配置（地区 / 并发 / 超时 / 数据源） |
| `pool:<协议>` | 该协议的原始候选池 |
| `best:<协议>` | 该协议的优选结果与进度 |
| `region:<协议>` | 该协议的地区过滤条件 |
| `meta` | 最近一轮运行摘要 |

需要清空数据，直接删对应的 Key 即可；只删 `pool:*` / `best:*` 会重新抓取，不影响密码和配置。

## 常见问题

**Q：面板提示「未绑定 KV 命名空间」？**
A：设置里的 KV 绑定**变量名称**必须填 `CSP`，改完保存并重新部署。

**Q：定时任务没反应？**
A：Cron 触发器需要在 Cloudflare 控制台自己绑，代码不会自动创建。判断是否真的跑过：打开面板概览页看「上次完成优选」时间，或在浏览器已登录 `/admin` 后于控制台执行
`fetch('/api/state').then(r=>r.json()).then(j=>console.log(j.meta))`，
看 `meta` 里有没有 `lastAuto` 字段——这个字段只有定时任务会写，手动优选不会。

**Q：定时任务某类报 `Too many subrequests by single Worker invocation`？**
A：撞上了 Cloudflare 单次调用的子请求数上限。定时任务是顺序跑各类，排在后面的协议容易额度不足。
可把「并发」调低（如 16 → 8），或调整 `autoTypes` 的顺序，把候选池最小、最容易失败的协议放到前面。

**Q：定时任务跑完，我的候选池怎么变小了？**
A：定时任务为控制请求量会先抽样再测，抽样结果会覆盖写回 `pool:<协议>`。
重新打开一次面板即可触发自动全量拉取，候选池会恢复完整；`best:<协议>`（优选结果）不受影响。

**Q：节点显示可用，但客户端连不上？**
A：这里测的是 **Cloudflare 侧**能不能通过该节点连通。免费代理本身不稳定，中途掉线、被封都很正常，多测几轮取延迟低的即可。

**Q：能不能只测一个国家？**
A：可以在对应协议页里选地区，设置里的「定时优选地区」也会约束定时任务的地区范围。
